P4.10 · Same agent, the SDK runs the loop

20 min · 2.4

The one idea: the loop you wrote by hand (call Claude, run the tool, send the result back, check stop_reason) is exactly what the Agent SDK does for you. You give it the tools, the rules and the hooks. It runs the loop.

Three terms:

  • Agent SDK: a library that runs the agentic loop for you, with the same machinery as Claude Code.
  • In-process MCP server: your tools, packaged as an MCP server that lives inside your own Python program. Their names get a prefix: mcp__shop__get_customer.
  • allowed_tools: the only tools this agent may use. Built-in tools such as Bash and file editing are switched off with disallowed_tools.

"""P4 session 2: the support agent on the Claude Agent SDK, with hooks and escalation rules."""
import asyncio
import json
import sys

from claude_agent_sdk import (
    AssistantMessage,
    ClaudeAgentOptions,
    ClaudeSDKClient,
    HookMatcher,
    ResultMessage,
    TextBlock,
    ToolUseBlock,
    create_sdk_mcp_server,
    tool,
)

import backend

MODEL = "claude-haiku-5-5"  # check docs.claude.com for current model names
REFUND_LIMIT = 500

state = {"verified_customer_id": None, "looked_up": set()}

SYSTEM = """You are a customer support agent for an online office-supply shop. Resolve requests with the tools. Be brief.

Escalation rules:
- Escalate at once, without trying to resolve, if the customer asks for a human.
- Escalate if policy does not cover the request. Policy covers: refunds for delivered orders that arrived damaged, with a photo; order status questions.
- Escalate if a tool tells you to, or if you cannot make progress after one retry.
- Do NOT escalate a case the policy covers, even if the customer is upset or rude.

Examples:
- "My mug arrived cracked, photo attached, order A-1." -> verify, look up, refund. No escalation.
- "This is useless, get me a manager now." -> escalate at once, reason "customer asked for a human".
- "I changed my mind about the colour, refund please." -> change of mind is not covered -> escalate, reason "policy gap".

When you escalate, fill every field of escalate_to_human so the human never has to ask the customer again."""


def reply(result: dict) -> dict:
    """Wrap a backend result as an MCP tool result, marking failures as errors."""
    return {"content": [{"type": "text", "text": json.dumps(result)}], "is_error": bool(result.get("isError"))}


@tool("get_customer", "Find and verify a customer by email. Call this FIRST, before any order or refund action.", {"email": str})
async def get_customer(args):
    result = backend.get_customer(args["email"])
    if not result.get("isError"):
        state["verified_customer_id"] = result["customer_id"]
    return reply(result)


@tool("lookup_order", "Get one order's item, amount, status and whether a damage photo was received. Only for the verified customer's own orders.", {"order_id": str})
async def lookup_order(args):
    if not state["verified_customer_id"]:
        return reply(backend.error("prerequisite", "Blocked: verify the customer with get_customer first.", False))
    result = backend.lookup_order(args["order_id"], state["verified_customer_id"])
    if not result.get("isError"):
        state["looked_up"].add(args["order_id"])
    return reply(result)


@tool("process_refund", "Refund one delivered order of the verified customer, after lookup_order. Amount must not exceed the order amount.", {"order_id": str, "amount": float})
async def process_refund(args):
    if args["order_id"] not in state["looked_up"]:
        return reply(backend.error("prerequisite", "Blocked: look up this order first.", False))
    return reply(backend.process_refund(args["order_id"], args["amount"]))


@tool(
    "escalate_to_human",
    "Hand the case to a human agent. Fill every field so the human can act without asking the customer again.",
    {"customer_id": str, "order_id": str, "what_customer_wants": str, "what_was_checked": str, "reason": str, "recommended_action": str},
)
async def escalate_to_human(args):
    print("\n--- HANDOFF TO HUMAN ---")
    for key, value in args.items():
        print(f"  {key}: {value}")
    return reply(backend.escalate_to_human(args["what_customer_wants"], args["reason"]))


async def refund_limit(input_data, tool_use_id, context):
    """PreToolUse hook: runs in code before every refund, whatever Claude decided."""
    amount = input_data["tool_input"].get("amount", 0)
    if amount > REFUND_LIMIT:
        print(f"\n[HOOK PreToolUse] blocked a refund of {amount}: over the {REFUND_LIMIT} limit")
        return {"hookSpecificOutput": {
            "hookEventName": "PreToolUse",
            "permissionDecision": "deny",
            "permissionDecisionReason": f"Refunds over {REFUND_LIMIT} need a human. Do not retry. Call escalate_to_human with a full handoff.",
        }}
    return {}


async def audit(input_data, tool_use_id, context):
    """PostToolUse hook: runs after every tool and writes an audit line."""
    line = {"tool": input_data.get("tool_name"), "input": input_data.get("tool_input"), "output": input_data.get("tool_response")}
    with open("audit.jsonl", "a") as f:
        f.write(json.dumps(line, default=str) + "\n")
    return {}


async def main(prompt: str) -> None:
    server = create_sdk_mcp_server(
        name="shop", version="1.0.0", tools=[get_customer, lookup_order, process_refund, escalate_to_human]
    )
    options = ClaudeAgentOptions(
        model=MODEL,
        system_prompt=SYSTEM,
        max_turns=12,
        mcp_servers={"shop": server},
        allowed_tools=[
            "mcp__shop__get_customer",
            "mcp__shop__lookup_order",
            "mcp__shop__process_refund",
            "mcp__shop__escalate_to_human",
        ],
        disallowed_tools=["Bash", "Read", "Write", "Edit", "Glob", "Grep", "WebFetch", "WebSearch"],
        hooks={
            "PreToolUse": [HookMatcher(matcher="mcp__shop__process_refund", hooks=[refund_limit])],
            "PostToolUse": [HookMatcher(hooks=[audit])],
        },
    )
    async with ClaudeSDKClient(options=options) as client:
        await client.query(prompt)
        async for message in client.receive_response():
            if isinstance(message, AssistantMessage):
                for block in message.content:
                    if isinstance(block, TextBlock):
                        print(f"\nAGENT: {block.text}")
                    elif isinstance(block, ToolUseBlock):
                        print(f"  -> {block.name}({block.input})")
            elif isinstance(message, ResultMessage):
                print(f"\n[done] turns: {message.num_turns}, stop_reason: {message.stop_reason}, result: {message.subtype}")


if __name__ == "__main__":
    asyncio.run(main(" ".join(sys.argv[1:]) or "Hi, I'm anna@example.com. Order A-5001, the lamp arrived broken, photo sent. Refund please."))

P4.11 · A hook that blocks big refunds

20 min · 1.5 1.4

The one idea: a hook is your code, run by the SDK at a fixed moment, for example just before a tool runs. Claude cannot skip it or talk its way past it. Here, any refund over 500 is stopped, and Claude is told to hand the case to a person.

Two terms:

  • PreToolUse hook: runs before a tool call. It can allow it, block it (deny), and tell Claude why and what to do instead.
  • PostToolUse hook: runs after a tool returns. It can log, check or add notes to the result.

Find refund_limit() in sdk_agent.py, and the line in ClaudeAgentOptions that attaches it only to mcp__shop__process_refund.

P4.11.1 · Ask for the big refund

To test the hook alone, the case must pass every other rule: delivered, damaged, with a photo, and over 500. A-5002 has no photo, so Claude stops earlier to ask for one. Add one order that passes everything except the limit.

uv run python sdk_agent.py "Hi, I'm anna@example.com. The standing desk from order A-5003 arrived broken, I sent a photo. Refund the full 820 please."

Checkpoint ✅ Look for this order of events:

  1. get_customer and lookup_order run normally.
  2. Claude tries process_refund with 820, and you see [HOOK PreToolUse] blocked a refund of 820.
  3. Claude does not retry. It calls escalate_to_human, and --- HANDOFF TO HUMAN --- prints all six fields.

If you ran the A-5002 chair case first: Claude asked for a photo and stopped. That is correct. The missing photo is a fact it can still get from the customer, so it asks before it refunds or escalates. The hook never fired because Claude never tried the refund.

Read the handoff. Could a person act on it without contacting Anna? That is the test of a good handoff.

The exam lens, in plain words.

1. A business limit that must never be broken (refunds over a limit, deletes, payments) belongs in a hook or a gate, not only in the prompt.

2. A PreToolUse hook can do more than block: it tells Claude the reason and the next step ("call escalate_to_human"). That turns a dead end into a redirect.

3. A PostToolUse hook acts on a result: log it, check it, or clean it up (for example, one date format) before Claude reasons over it.

4. A handoff is a structured summary: who, what they want, what was checked, why it is escalated, what to do next. The person should never have to ask the customer again.

Trap answer to spot: "add 'never refund more than 500' to the system prompt". It works most of the time. A rule about money must work every time.

P4.12 · When to hand over to a person

20 min · 5.2

The one idea: escalate too often and nothing gets resolved. Escalate too rarely and the agent bluffs on cases it should not handle. Clear written rules and a few examples set the line. This is this morning's Question 3, built.

P4.12.3 · Not covered by policy

Write down: did all three match your prediction?

The exam lens, in plain words.

1. The agent escalates the wrong cases: write explicit criteria for when to escalate and when not to, plus a few examples of borderline cases. Try this first, before anything bigger.

2. The customer asks for a person: escalate at once. Do not try to solve it first.

3. Policy does not cover the request: escalate, and say it is a policy gap. Do not invent a policy.

4. The agent cannot make progress (repeated failures): escalate with what was tried.

Trap answers to spot: "escalate when the customer sounds angry". Anger says nothing about how hard the case is. And "train a model on past tickets first": a bigger fix before the first fix.

P4.15 · Quick reference card

Agent SDK: runs the loop for you. Tools = @tool functions in an in-process MCP server, named mcp__server__tool.
PreToolUse hook: before a tool runs. Allow, deny, or deny and redirect ("call escalate_to_human").
PostToolUse hook: after a tool returns. Log, check, clean up the result.
Must never happen: hook or gate in code. Prompt rules alone are requests.
Escalate: customer asks for a person (at once) · policy gap · cannot make progress. Not: anger alone.
Fix wrong escalations: explicit criteria + borderline examples, first.
Handoff: who, wants what, what was checked, why, recommended next step.
